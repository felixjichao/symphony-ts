# Agent Note: Decision and Web execution continuity
Status: proposed

## Problem

A renewable browser lease is permission, not progress. Reloads reset local recovery decisions, and losing a tab can lose the only evidence that a prompt was sent. Recovery must preserve exact-HEAD approval, receipts and both claim and binding fences (SPEC §4 extension, §7/§8/§14 adjacency).

## Decision

Persist optional execution metadata in the existing schema-v1 Decision store, keyed by immutable task/revision. Legacy stores remain readable. Claim establishes a ten-minute grace baseline; advanced execution stages or growth of the new assistant turn extend the deadline. Heartbeats, checkpoint timestamps, repeated stages and navigation do not. Deadline expiry refuses further lease renewal; only the work-aware host delegates expired reclaim. A valid lease with expired progress is diagnosed stalled while awaiting expiry, never forcibly stolen.

The authority counts at most three reclaim/rebind mutations across claims, bindings and store restarts. Rebind operation receipts remain idempotent and do not consume additional attempts. A missing executor after a possible prompt/bootstrap/result is blocked for receipt/conversation inspection, never authorized to replay. Recovery exhaustion is also a durable nonterminal block. Counters only reset through explicit operator authorization or a new task. Protected starts, heartbeat, bindings and results reject blocked execution. Block facts include cause, timestamp and unblock instruction and contain no conversation text or credentials.

The browser awaits a fenced progress commit before navigation and before either Send click. Local transport failures consume an additional checkpoint-persistent six-failure cap; terminal status and receipt lookup precede exhaustion handling, so an accepted result still wins. A mapped human barrier, unrecoverable binding or unmapped adapter failure writes a block without creating a terminal failure or submission receipt. The executor exposes a blocked outcome. Existing result receipt matching remains unchanged.

Persist enabled/Stop per bridge URL in userscript storage; migrate the prior tab-local enabled flag once, with a persisted Stop taking priority. A new page starts automatically and uses its own checkpoint identity. It never imports another tab's lease token. Decision claim serialization prevents two owners. A bridge authorization failure retains intent, stops execution and uses read-only probes (30 seconds, then 60 seconds) until authorization returns. Explicit Stop cancels probes; other running pages observe persisted Stop before their next poll, heartbeat, navigation or Send. Without an owner the host reports a configured browser-page wait; it does not launch a browser.

## Alternatives considered

- Use heartbeat/checkpoint age as progress: rejected because a frozen executor can renew forever.
- Steal a valid lease: rejected because expired-claim authority already provides transactional fencing.
- Adopt a lost tab's token or resend a possibly submitted prompt: rejected because checkpoints cannot confer authority or prove absence of side effects.
- Add blocked to every task-status consumer: rejected in favor of native execution metadata and an explicit nonterminal block endpoint.
- Clear enabled on bridge 401/403: rejected because authorization recovery would then require manual Start.
- Introduce OS browser supervision or general incident storage: outside the confirmed boundary and neighboring #150 responsibilities.

## Consequences

`POST /v1/tasks/:id/block` validates live claim/binding credentials. Privileged `POST /v1/continuity/unblock` requires the exact revision, claim generation, binding generation and lease expiry; the operator must first inspect uncertain effects. It releases/fences the old attempt and permits a fresh decision, not a continuation under an old token. Browser polling never calls unblock. The native record retains the latest blocked cause and cumulative attempt count rather than a separate workflow or incident log. Progress time starts as a grace baseline; the host reports it unknown until an actual advanced stage exists.

Conservative blocks can need operator inspection after tab identity loss. Background throttling or a response with no visible growth for ten minutes can exhaust its progress grace; no automatic login is attempted. Real ChatGPT/Tampermonkey close/reopen, authentication and network-interruption acceptance remains required separately from fixture tests. The standalone cleanup bundle is regenerated by the repository build because it embeds Decision service/store code.

The production Bridge CLI injects a fresh read-only GitHub PR observation before browser navigation/Send and rebind: the PR must still be open at the exact task HEAD. Missing/unreadable facts deny mutation. Native task status, lease and binding are revalidated in the transaction after this I/O. Embedders constructing `DecisionService` directly supply the equivalent `authorizeExecution` port for external target authority; the store does not import tracker or own GitHub policy.
