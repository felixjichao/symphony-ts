# Agent Note: Work-level continuity reconciliation
Status: accepted

## Problem

Locally valid task, retry and Delivery records can leave active work without an executor. Running-worker reconciliation alone cannot discover these gaps. The approved NEST-138 plan targets baseline `4655820` independently of other implementations of GitHub #147.

## Decision

Keep observation contracts in domain (§4 adjacent) and a thin coordinator in orchestrator (§7/§8/§14). A scan unions active tracker identities with known runtime, Decision and managed Delivery references. Every identity still requires refreshed tracker facts. CLI composition reads native sources, never Operations projections. Stage derivation uses planning admission, pending/leased tasks, marker-validated PR HEAD/CI, completed current-HEAD review verdicts and paused handoff state. GitHub work uses the existing marker-validated Delivery observer regardless of local workspace or `.git` existence. Missing observation context or failed remote reads are unavailable, never evidence that the remote PR/stage is absent.

The protocol is observe, derive, re-observe/version-check, delegate once, then re-observe. A failed post-action read is unverified; it never triggers immediate replay. Before delegation, the coordinator retains the exact request (WorkKey, action, task/revision/lease/binding/expiry or handoffId/HEAD) in process memory. A thrown call, explicit uncertain result, or failed/unavailable readback retains that request across scans. Poll/retry coding admission also refuses unresolved work. Subsequent scans still observe, but elapsed time, heartbeat telemetry and unrelated version changes do not authorize another delegation. Unresolved diagnostics require human verification. Native evidence alone can release suppression: the exact claim is released/terminal or invalidated by revision/generation/binding/lease renewal; the persisted handoff is completed or replaced. Missing records and failed reads are not evidence. An acknowledged successful action plus available readback, or an explicit no-commit refusal, also settles the invocation. This is process-local protection, not durable exactly-once delivery. Diagnoses remain derived memory, available through `host.workContinuity.observations`, with no capability lease token or new persisted lifecycle. Admission prevents the normal candidate loop from dispatching coding into a different stage or after observation failure. The existing authority remains the only dispatcher and retry scheduler.

Poll and retry launches use the authority's asynchronous `refreshDispatch` port immediately before the existing synchronous eligibility/commit segment. The port returns the newly observed Issue, not a reusable permission bit; the host no longer maintains an admission cache. Poll inventory failure ends candidate dispatch for that tick. A per-work source failure refuses candidate dispatch; a retry source failure retains its reservation through bounded backoff (`admission_refresh_failed`). An explicitly blocked or non-coding stage rejects execution without automatically retrying it. Decision and local Delivery are checked again after slow remote reads, so a mixed snapshot cannot grant coding admission.

The authority rechecks shutdown and lifecycle generation after poll admission, and retry-token ownership after retry admission. Native slot, claim, state and planning eligibility remain synchronous commit checks. Shutdown waits for in-flight admission reads. A superseded retry cannot consume a newer reservation or start a worker when its remote read eventually finishes.

Decision reclaims only an expired lease, transactionally checking task revision, claim generation, binding generation and exact observed expiry. Renewals and competing reclaims fence stale requests. Local service and authenticated bridge share this primitive. The bridge performs an initial sweep and a non-overlapping lifecycle-owned periodic sweep without reopening another store. Review target matching uses repository + PR + HEAD before selecting a task or completed verdict; numeric revisions are comparable only within that target. Other targets remain in active-conflict checks. Multiple unfinished tasks block recovery and coding; terminal history does not. A lone review without a matching remote target is contradictory. Native result validation binds task ID/revision and exact target. A managed merged PR with active tracker work and no blocker/ownership conflict is an external tracker-sync wait, not another merge or coding request. A single exact-target pending or expired review cannot mask that merged fact or trigger reclaim; a valid review lease is retained without cancellation/release, and its binding/ownership fences remain checked before external wait. Explicit blocking and other-target/multiple-task conflicts retain priority. Tracker terminal state ends the wait; source failure is unavailable. Pending tasks still need an executor; a service name alone does not establish liveness. A valid lease with no business progress is unknown, not reclaimable.

Codex meaningful progress is a new stable lifecycle transition or increased absolute usage. Generic notifications, PID and duplicate usage do not reset stall. Existing timeout configuration, disable semantics and strict greater-than boundary remain. Last event time stays observational telemetry.

File-backed Delivery run, halt and compensation share an exclusive filesystem authority lock. Run/recover library entry points acquire the storage's exclusive capability as well. Automatic compensation re-reads identity/handoff version under that lock before invoking the existing recovery function. Lock age is never evidence that a mutation can be repeated; a leftover crash lock requires operator verification and removal. Completion of reporting does not unpause work. Native in-memory storage adapters remain responsible for their own concurrency when used outside the file-backed host.

## Alternatives considered

- Put recovery in Operations: rejected because read-model anomalies do not authorize mutations.
- Reuse a prior scan's boolean admission: rejected because a pause, Decision claim, remote HEAD or stage change can occur before a retry timer fires. Launch reads its own authoritative facts.
- Replay the last CLI command: rejected because task revision, HEAD, binding, admission and pause state may have changed.
- Rely on coordinator single-flight or atomic file rename: rejected because separate coordinators/processes can still race. Decision checks inside its transaction; Delivery locks the mutation authority across all supported entry points.
- Retry an uncertain side effect after a fixed timeout: rejected because time and unrelated snapshots cannot prove non-commit. Retain suppression until native evidence resolves the target, accepting manual intervention when evidence is insufficient.
- Claim unknown Web progress is stale: rejected because heartbeat only establishes execution permission. Browser progress/deadline policy belongs to #148.

## Consequences

No new production dependency from orchestrator to Decision/Operations. Recovery is bounded to one authority delegation per work per scan; the scheduler consumes its own queued/due retry. Stop synchronously rejects new recovery and waits for in-flight work.

Unsafe or absent native primitives return `unsupported` with the responsible authority and stranded diagnosis. In particular the coordinator does not automatically start a browser, invent missing retry timers, run repair commands, or authorize merge. Coding proceeds through the ordinary dispatch path. Cross-restart intent/timer restoration (#149), browser recovery (#148), and durable incidents/multi-round policy (#150) remain outside this change. Delivery context conventions remain the existing `symphony/<identifier>` and `main`; nonstandard contexts fail closed through ownership validation. Real GitHub/Codex smoke is opt-in and is not implied by fixture validation.
