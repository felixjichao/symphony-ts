# SPEC Conformance Matrix

实现进度与官方 SPEC 验收项（§17 Test and Validation Matrix、§18 Implementation Checklist）的可追踪映射。规范 baseline 与升级规则见 [upstream.md](upstream.md)；owner 包的职责边界见 [architecture.md](architecture.md)。

## 规则

1. **状态词汇**：`planned M#`（已排入里程碑）→ `in-progress`（实现中）→ `implemented`。**只有代码 + 验收测试都落地后才能标 `implemented`**，Test 列同时从 `—` 变为可复跑的测试入口。
2. **每个 milestone PR 必须更新对应行**（Status 与 Test 列），属于 review 的一部分；不更新矩阵的实现 PR 不完整。
3. **升级 SPEC baseline 时优先 diff 本表**：新增 / 变化的 section 先补行或改标注，再排期实现（流程见 [upstream.md](upstream.md)）。
4. Test 列填写对应 SPEC §17 validation profile（`Core Conformance` / `Extension Conformance` / `Real Integration Profile`）与 §18 checklist 项的可复跑入口（如 `npm test -w @symphony/config` + 具体测试文件）。

**M3.1 落地（M3.1 / #27）**：`@symphony/workspace` 建立公共管理内核 `WorkspaceManager` 与工厂函数 `createWorkspaceManager`，直接复用 `@symphony/domain` 的 `deriveWorkspaceKey`，实现确定性目录计算、缺失目录创建与已有目录复用。针对 SPEC §17.2 实现裁定的 existing non-directory 场景采用 Fail Safely 策略（绝不自动删除或替换未知文件/符号链接，抛出类型化 `existing_non_directory` 错误，见 [workspace non-directory policy Agent Note](../notes/accepted/architecture/2026-09-29-workspace-non-directory-policy.md) 与 [packages/workspace/README.md](../packages/workspace/README.md)）。路径 containment 校验（#28）与 hooks / cleanup（#29）随后续里程碑落地。

**M3.2 落地（M3.2 / #28）**：`@symphony/workspace` 在 M3.1 内核之上叠加 filesystem safety boundary（SPEC §9.5）：`validateWorkspacePath`（discriminated 结果）与 `assertWorkspacePathSafe`（throwing 形态）实现 absolute + lexical containment + canonical（每次实时 `realpath`，不缓存）containment 的完整校验，覆盖 root equality、symlink escape、尚不存在路径的 ancestor 推定与 root 自身含 symlink 时的 canonical root 权威；`unsafe_path` 错误经 `unsafeReason` 子字段细分为 `workspace_equals_root` / `workspace_outside_root` / `workspace_symlink_escape` / `workspace_path_unreadable` 四类拒绝面（顶层错误码集合保持 M3.1 已发布契约不变）；`createWorkspace` 的复用与新建路径均接入 safety gate。`assertWorkspacePathSafe` 是 M4（agent launch 前）与 #29 / M5（destructive cleanup 前）必须复用的 execution-boundary primitive——**§17.2 最后一项 "Agent launch uses the per-issue workspace path as cwd and rejects out-of-root paths" 仍属 planned M4**：M4 必须证明 launch 前重新执行安全校验、subprocess 实际 `cwd === workspace.path`、unsafe workspace 拒绝启动。决策见 [workspace path safety Agent Note](../notes/accepted/architecture/2026-09-30-workspace-path-safety-contract.md)。
